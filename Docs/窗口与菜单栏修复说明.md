# 窗口无法打开 / 菜单无响应 —— 修复说明

> 2026-11-23 00:42

## 用户报告的两个问题

1. **双击图标没有桌面窗口**
2. **菜单栏「打开设置」没反应**

## 根因分析

### 问题 1：双击无窗口
`Info.plist` 中 `LSUIElement = true`，应用被标记为**纯菜单栏应用**：
- 系统不分配 Dock 图标
- 访达双击 .app 时不会自动创建窗口
- 这是 macOS 的既定行为，不是 bug

### 问题 2：菜单栏「打开设置」无响应
原实现依赖 SwiftUI 的 `Settings` 场景 + `showSettingsWindow:` selector：
```swift
NSApp.sendAction(Selector(("showSettingsWindow:")), to: nil, from: nil)
```
在 `LSUIElement=true` 的应用上，该 selector 经常**找不到目标而静默返回 false**，
用户点击后毫无反应——这正是实测到的现象。

## 修复方案

### 1. 改用 AppKit 手动创建窗口
新增 `WindowController.swift`：
```swift
let hosting = NSHostingView(rootView: SettingsView(controller: controller))
let win = NSWindow(contentRect: ..., styleMask: [.titled, .closable, .miniaturizable], ...)
win.contentView = hosting
win.makeKeyAndOrderFront(nil)
NSApp.activate(ignoringOtherApps: true)
```
行为完全可控，不依赖 SwiftUI 场景机制。

### 2. 双击时打开窗口
实现 `applicationShouldHandleReopen`：
```swift
func applicationShouldHandleReopen(_ sender: NSApplication, hasVisibleWindows flag: Bool) -> Bool {
    windowController?.showSettingsWindow()
    return true
}
```
访达双击 .app 时会触发此回调，从而打开设置窗口。

### 3. 菜单栏「打开设置」直连 WindowController
```swift
@objc private func openSettings() {
    windowController.showSettingsWindow()
}
```
不再经过 selector 转发。

## 验证结果（全部实测通过）

| 测试 | 结果 |
|---|---|
| 双击图标（再次 open） | ✅ 日志「设置窗口已打开」，窗口数 = 1 |
| 菜单栏图标点击 | ✅ 菜单展开，显示 3 项 |
| 菜单栏 → 打开设置 | ✅ 窗口数 = 1 |
| 窗口标题 | ✅「GlideCut 设置」 |
| 窗口尺寸 | ✅ 460 × 592 |
| 窗口内容渲染 | ✅ 平均亮度 94.0，std 88.2（有真实内容，非空白） |
| 窗口关闭 | ✅ 日志「设置窗口已关闭」，窗口数 = 0 |

## 关于 LSUIElement 的取舍

保持 `LSUIElement = true`（符合产品定义「不需要一直显示 Dock 主窗口」），
通过 `applicationShouldHandleReopen` 让双击也能看到窗口，两者兼得：
- 平时：纯菜单栏应用，不占 Dock
- 双击：打开设置窗口
