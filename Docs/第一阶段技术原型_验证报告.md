## 一、本阶段完成内容

### 1. 事件转换架构（新增）
- `Core/WheelTransformer.swift`（新增）：滚轮事件 → FCP 操作的转换器
  - 仅当 **FCP 是前台应用** 时才处理，其他应用零影响
  - 仅当命中指定修饰键时才消费事件，未命中一律放行
  - 内置节流（50ms），避免高频滚动把 FCP 菜单刷爆
- `Core/EventTapController.swift`（改造）：从 listen-only 改为**可拦截模式**
  - 回调返回 `Bool` 决定是否消费事件
  - 增加自身注入事件标记（`eventSourceUserData`），防止事件循环
  - 增加 `tapDisabledByTimeout` / `tapDisabledByUserInput` 自动恢复
- `Core/EventController.swift`（改造）：接入转换器，统计转换次数

### 2. Bug 修复
- `Core/FrontmostAppInfo.swift`：FCP bundle id 从错误的 `com.apple.FinalCutPro`
  修正为实测值 **`com.apple.FinalCutApp`**，并保留兼容集合。

### 3. macOS 13.0 兼容（已完成）
- 部署目标 27.0 → **13.0**
- 修复 4 处 macOS 14+ API（详见 `macOS13兼容性说明.md`）

| 退出后停止监听 | ✅ | 事件循环正常退出，无残留 |

### ❌ 关键失败项（已定位原因）

| 尝试 | 结果 | 原因 |
|---|---|---|
| 合成 `Command + =` 键盘事件缩放 | **完全无效（0.00% 变化）** | **FCP 忽略 CGEvent 合成的键盘事件** |

这是个重要技术结论：**不能用合成快捷键驱动 FCP**，必须走菜单（AX）。

### 🔧 找到并验证的可行方案

**通过辅助功能驱动 FCP「显示 > 放大/缩小」菜单**：
- 实测菜单点击后时间线区域变化 **47.6%**（单次）
- 完整链路验证：`Command+滚轮 → 菜单「放大」→ 时间线变化 18.1%` ✅

## 五、未解决问题

1. **Option+滚轮水平移动未验证**：代码已实现（注入水平滚动事件），但 FCP 是否响应水平滚动事件尚未实测。
2. **普通滚轮 / Shift+滚轮 原生行为未对比验证**：需要「GlideCut 运行 vs 退出」的 A/B 对比测试。
3. **快速滚动稳定性未测**：未做快速甩滚轮的压力测试。
4. **菜单驱动依赖辅助功能权限**：需在设置界面做权限检测与引导。
5. **菜单驱动可能有延迟**：AX 菜单操作约 20ms 级，高频滚动时的流畅度待优化。
6. **GlideCut 应用内监听开关需手动点击**：目前验证走的是探针工具，应用内还需要用户从菜单栏开启。

## 附：重要技术备忘

- **FCP 忽略合成键盘事件**（实测确认）——这是本项目最关键的发现，决定了架构必须走 AX 菜单路径。
- **FCP 窗口可能被压成 1 像素**（`size = 2540,1`），用 `Control+Command+F` 全屏切换可恢复。
- **FCP 12.4 bundle id = `com.apple.FinalCutApp`**。
- 测试期间发现用户 FCP 中打开了真实婚礼项目，已停止操作并交由用户检查。
