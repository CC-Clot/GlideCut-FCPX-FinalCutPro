# 水平平移「用一下能用、再用又不能」—— 根因与修复

> 2026-11-23 18:20 ｜ 基于真机日志取证
> 状态：**根因已定位、代码已修复、编译与 24 项测试通过；待真机复验**

---

## 一、现象

Option / Control 映射切换后，水平平移一开始可用，用一会儿后失效；
Command+滚轮缩放始终正常。

## 二、根因（有日志数据支撑，非推测）

从 `~/Library/Application Support/GlideCut/glidecut.log` 取证：

- 按住 Option 滚动时，真实事件 flags = `0x80020`（524320）
  - `0x80000` = 高位语义位 `maskAlternate`（Option）
  - `0x20` = **低位设备位「左 Option 键」**（NX device mask）
- 上一版 `shiftedFlags` 只改了高位：`0x80020 → 0x20020`（131104）
  - 高位已是 Shift，但**低位仍写着「按着 Option」**
- 真实 Shift+滚轮的正确 flags 应为 `0x20002`
  - 高位 `0x20000`（maskShift）+ 低位 `0x02`（左 Shift）

**两条修饰键信息（语义位 vs 设备位）互相矛盾**，系统/FCP 在判断是否为原生
Shift+滚轮时，低位设备位也参与判定，因此出现「时灵时不灵」的不稳定表现。

> 这解释了为什么日志里映射事件一直在触发（649 次）、flags 改写数值看起来也「对」，
> 但真机水平平移不稳定 —— 因为改写后的事件并不是一个自洽的真实 Shift+滚轮。

### 为什么 Command 缩放不受影响
缩放走的是 AX 菜单点击（`显示 > 放大/缩小`），完全不依赖事件 flags 改写，
所以始终稳定。

## 三、修复

`ModifierState.shiftedFlags(from:replacing:)` 现在**同时改写两组位**：

| 输入（Option） | 旧输出（错误） | 新输出（正确） |
|---|---|---|
| `0x80020` | `0x20020` | `0x20002` |

- 高位：去 `.maskAlternate` / `.maskControl`，加 `.maskShift`
- 低位：去左/右 Option（0x20/0x40）或左/右 Control（0x08/0x10），加左 Shift（0x02）
- 其余标志位（如 Command、数字键盘、非合并标志）原样保留

映射日志现改为十六进制打印（`flags: 0x80020→0x20002`），便于下次真机直接核对。
