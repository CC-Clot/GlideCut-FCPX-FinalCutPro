## 一、重要更正（必须记录）

### ❌ 撤回：Option+滚轮水平平移「已成功」的结论

**我此前报告「Option 平移突破，变化 3.163%」是错误的。**

复核过程：
- 当时参数：`wheel2=-300, units=.pixel, 30帧, 带 scrollPhase`
- 当时观测：界面变化 3.163%，集中在 y=864-1728
- **现在用完全相同参数复现：0.002%（无变化）**

**结论：那 3.163% 是窗口重绘/动画造成的假阳性，不是真实的时间线平移。**

按项目要求「不得虚报测试通过」，特此更正。

### 同时修正的另一个判断

FCP 时间线水平滚动条：
```
AXHidden = 1（隐藏）
actions = ()  （无任何可执行动作）
```
即使 `AXValue` 能读到（0.0 / 0.5307），**设置它也不会驱动时间线视图**。
实测设值后判断画面无变化、滚动条值也不被 FCP 保留。

### 关键技术发现（高价值）

**FCP 忽略 CGEvent 合成的键盘事件和普通滚轮事件。**
- 合成 `Command + =`（FCP 官方快捷键）→ **0.00% 无变化**
- 合成普通滚轮 → **0.002% 无变化**
- 只有通过 **AX 菜单驱动**（`显示 > 放大/缩小`）才有效 → **47.6% 变化**

这一发现决定了架构必须走 AX 菜单路径。

## 三、未解决（诚实记录）

### Option+滚轮水平平移 —— 未实现

尝试过并全部失败：
1. 合成水平滚轮事件（普通形态）→ FCP 忽略
2. 合成触控板式事件（带 scrollPhase）→ 无稳定效果
3. AX 设置时间线滚动条值 → 滚动条隐藏且无 action，设值不生效
4. 查找 FCP 菜单 → 「时间线滚动」是勾选项，无水平平移命令

**可能方向**（未验证）：
- FCP 的 `scrollToVisible` AX 动作
- 通过 `AXUIElementCopyParameterizedAttributeValue` 操作时间线内容
- 模拟触控板硬件事件（需要 IOKit，复杂度高）
