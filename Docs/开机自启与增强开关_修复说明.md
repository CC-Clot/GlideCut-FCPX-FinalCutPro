# 开机自启动与滚轮增强开关 —— 修复说明

> 2026-11-23 02:00

## 用户提出的三点

1. 重启电脑后菜单栏图标在，但增强开关没启动；要求开机自启动打开后默认开启增强
2. 开机自启动与滚轮增强开关不冲突，增强必须能手动关闭
3. 开机自启动配置放到滚轮增强右边，不单独占一行

---

## 问题 1 的根因（排查过程）

### 表面现象
`listeningEnabledByUser = 0` —— 上次手动关闭被持久化，导致重启后不自动开启。

### 更深层的问题
排查中发现 `SMAppService.mainApp.status = 3 (notFound)`！
说明**系统层面的登录项注册其实没生效**，`launchAtLogin = 1` 只是写进了 UserDefaults。

**根因**：`launchAtLogin` 的 `didSet` 只在「值发生变化」时触发注册。
如果值已是 `true` 但系统未注册（例如签名变化导致注册失效），
就永远不会有第二次注册尝试。

### 修复
1. **启动时主动同步登录项状态**（`synchronizeLoginItem()`）
   ```swift
   let want = launchAtLogin
   let registered = (service.status == .enabled)
   if want && !registered { try service.register() }
   ```
2. 实测验证：`登录项状态正常：want=true registered=true`
   系统登录项列表确认：`Disposition: [enabled, allowed, notified]`

## 需求语义的澄清与实现

### 尝试过但放弃的方案

| 方案 | 问题 |
|---|---|
| 用 `systemUptime < 120` 判断开机自启 | 重启后手动双击也会误判 |
| 用 `utmpx` 登录时间差值判断 | 同上，容差内无法区分 |
| 用 `XPC_SERVICE_NAME` 判断 | **实测手动双击与自启动完全相同** |
| 用 `sfltool dumpbtm` 查询 | 只能查注册状态，查不到启动来源 |

**结论：macOS 没有提供可靠的 API 来区分「开机自启动」与「手动双击」。**

### 最终实现（按用户意图）

不区分启动来源，统一规则：

```
每次启动（含开机自启、手动双击）  →  默认开启滚轮增强
手动关闭增强                      →  仅本次会话生效
下次启动                          →  再次默认开启
```

代码：
```swift
// AppDelegate
EventLog.shared.log("按产品规则：每次启动默认开启滚轮增强")
if PermissionStatus.isReady {
    controller.startListening()
}
```

```swift
// EventController.stopListening() —— 不再持久化"关闭"状态
// 手动关闭只影响本次会话，下次启动仍默认开启
```

## 需求 2：两个开关互不冲突 ✅

- **滚轮增强**：控制 CGEventTap 是否运行（`controller.isListeningBinding`）
- **开机自启动**：控制系统登录项（`settings.launchAtLogin` → `SMAppService`）

两者完全独立：
- 开自启动 ≠ 强制开启增强（增强可手动关）
- 关增强 ≠ 取消自启动
- 各自持久化，互不覆盖

## 需求 3：UI 布局调整 ✅

**修改前**：开机自启动独占一个 Section
**修改后**：合并到「通用」Section，位于滚轮增强**右侧同一分组内**

```swift
SettingsCard(title: "settings.section.general") {
    // 第一行：滚轮增强
    HStack { Text("启用滚轮增强"); Spacer(); Toggle(...) }
    Divider()
    // 第二行：开机自启动
    HStack { Text("开机时启动"); Spacer(); Toggle(...) }
}
```

窗口高度同步调整为 480×560。
