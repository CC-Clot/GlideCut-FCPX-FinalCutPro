# 开关反键修复 + 默认开启实现

> 2026-11-23 01:02

## 一、问题 1：菜单栏与窗口开关「反键」

### 根因
| 位置 | 更新机制 |
|---|---|
| 设置窗口 Toggle | SwiftUI 绑定 `isListeningBinding`，**响应式实时更新** ✅ |
| 菜单栏 NSMenuItem | 只在 `toggleListening()` 里手动调 `refreshState()`，**被动更新** ❌ |

所以在**设置窗口**里改开关时，菜单栏不会刷新 → 两边状态不一致（反键）。

### 修复
让菜单栏订阅 `EventController.$isListening`：

```swift
controller.$isListening
    .receive(on: DispatchQueue.main)
    .sink { [weak self] _ in
        self?.refreshState()
    }
    .store(in: &cancellables)
```

现在无论从哪个入口改状态，两边都实时同步。

## 二、问题 2：改为「安装后默认开启，手动关闭才记住」

### 实现
新增 `ListeningPreference`，用 `UserDefaults` 存用户意愿：

```swift
var isEnabled: Bool {
    get {
        if defaults.object(forKey: key) == nil {
            return true   // 从未设置 → 默认开启
        }
        return defaults.bool(forKey: key)
    }
    set { defaults.set(newValue, forKey: key) }
}
```

`AppDelegate` 启动时按意愿决策：
```swift
let userWantsEnabled = ListeningPreference.shared.isEnabled
if userWantsEnabled && PermissionStatus.isReady {
    controller.startListening()      // 自动开启
}
```

`EventController` 在开关时持久化：
- `startListening()` → `isEnabled = true`
- `stopListening()` → `isEnabled = false`

## 四、现在的用户行为

| 场景 | 行为 |
|---|---|
| 首次安装启动 | **自动开启**（无需任何操作） |
| 用户手动关闭 | 记住，下次启动保持关闭 |
| 用户重新开启 | 记住，下次启动自动开启 |
| 权限未授权 | 不开启，日志提示需要授权 |
| 退出应用 | 监听彻底停止 |

两个开关（菜单栏 / 设置窗口）现在**永远同步**。
