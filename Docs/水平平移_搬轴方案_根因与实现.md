# 水平平移 · 搬轴方案 —— 根因与实现

> 2026-11-23 19:55

## 一、三年试错的关键转折：真实事件基准的抓取

此前所有失败测试（7+1 种方案）都是**程序新建 CGEvent 再 post**（合成事件），
FCP 会过滤合成事件。而我们的「改写真实事件」方案虽然映射一直触发、flags 改写数值正确，
却始终「时灵时不灵」。

用纯监听探针（Verification/EventFingerprint.swift）抓真实 Shift+滚轮事件后，得到两个决定性事实：

1. **真实 Shift+滚轮的 flags = `0x20002`**（注意：探针早期版本的十六进制打印有 padding bug，
   把 `0x20002` 错打成 `0x20002000`，已修正）。
   → 说明我们从第一版起的 flags 改写数值**一直是对的**。
2. **真实 Shift+滚轮的增量在垂直轴**：`Δ1=-3, Δ2=0, phase=0/0`。

既然我们写入的 flags 与真实 Shift 完全一致，FCP 却不稳定响应，
结论只能是：**AppKit 在构造 NSEvent 时，可能用「物理按键实际状态（Option）」
覆盖了事件里的 Shift 标志**。物理按键状态无法用软件改写，这是「时灵时不灵」的根因。

## 二、参考 Mos 的成熟方案：搬轴

成熟开源滚轮工具 Mos（Caldis/Mos）的 Shift 转水平实现（ScrollPoster.swift）：

```swift
func shift(with nextValue: (y: Double, x: Double)) -> (y: Double, x: Double) {
    if shifting {
        // 按下 Shift：垂直有值、水平为空时，把垂直增量搬到水平轴
        if nextValue.y != 0.0 && nextValue.x == 0.0 {
            return (y: nextValue.x, x: nextValue.y)
        }
    }
    return nextValue
}
// 写入：
event.setDoubleValueField(.scrollWheelEventPointDeltaAxis1, value: v.y)
event.setDoubleValueField(.scrollWheelEventPointDelta2Compat, value: v.x)  // 实际为 PointDeltaAxis2
```

核心：**不是伪造 Shift 标志，而是把垂直增量搬到水平轴**。
这样任何应用收到的都是真正的水平滚动事件，与修饰键状态无关。

## 三、本次实现（双管齐下）

`WheelTransformer.remapPanToShift` 同时做两件事，任一生效即成功、互不冲突：

1. **改 flags**：Option/Control → 真实 Shift `0x20002`（高低位同步）——保留原有路径。
2. **搬轴**：`PointDeltaAxis1→2`、`FixedPtDeltaAxis1→2`、`DeltaAxis1→2`，垂直轴清零——新增可靠路径。

关键点：
- 始终原地改写系统产生的真实事件（来源 hidSystemState、相位、时间戳不变）；
- 绝不新建事件再 post（历史上 9 种失败方案的共同点）；
- 仅在「垂直有值、水平为空」时搬运，不破坏原生水平滚动。

## 五、真机验证方法

1. 运行 `更新安装_功能映射版.command` 重装。
2. 设置中平移键设为 Option（或 Control）。
3. 在 FCP 时间线上连续多次滚动 Option+滚轮，观察是否稳定水平平移。
4. 若仍有异常，查看 `~/Library/Application Support/GlideCut/glidecut.log` 中
   `功能映射：...→Shift+水平... Δ1→Δ2` 记录是否持续出现，并发我分析。

## 六、若本方案仍失败（预先记录的退路）

若搬轴后 FCP 仍无响应，说明 FCP 时间线既不认 Shift 标志也不认水平轴增量，
只剩两条路：
1. 改产品定义：用键盘快捷键替代滚轮平移；
2. 走 IOKit 虚拟设备模拟真实硬件输入（复杂度高、需签名，见历史文档「可能方向」）。

在此之前不再盲目改代码——必须以真实事件基准为依据。
