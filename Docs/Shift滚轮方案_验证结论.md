# Shift+滚轮映射方案 —— 验证结论

> 2026-11-23 01:40

## 你的方案

放弃 FCP 程序化接口，改用系统级滚轮事件映射：
- Option + 滚轮（默认）→ 转换为 FCP 原生 Shift + 滚轮
- Control + 滚轮（可选）→ 同样转换
- Shift + 滚轮不再保留
- 仅 FCP 前台生效

## 执行情况

### ✅ 已完成的部分

1. **代码实现完成**
   - `performPan` 已改为：拦截 Option/Control + 滚轮 → 合成 `Shift + 滚轮` 事件
   - 投递层级改为 `.cghidEventTap`（session 层无效）
   - 使用 `CGEventSource(stateID: .combinedSessionState)` 提升事件真实度
   - 设置界面：平移选项限定为 **Option（默认）/ Control**

2. **Command 缩放未被破坏** ✅
   - 实测验证：2.187% 界面变化，功能正常

3. **编译与测试** ✅
   - Debug / Release / Probe / Tests 全部 SUCCEEDED
   - 18 个单元测试 0 失败

### ❌ 关键技术结论：方案不可行

**严格复现测试（5 次）**：
```
第1次: 236 像素 (0.002%)
第2次: 236 像素 (0.002%)
第3次:  44 像素 (0.000%)
第4次: 236 像素 (0.002%)
第5次:  44 像素 (0.000%)
```

**排除干扰验证**：关掉 GlideCut 监听后，用独立程序注入 HID 层 Shift+滚轮 —— 同样 **0.002% 无变化**。

**结论：FCP 忽略所有合成的 Shift+滚轮事件，无论从哪个层级投递。**

### 过程中的误判（诚实记录）

测试中曾出现一次 1.978% 的变化，我当时报告为"突破"。但严格复现 5 次均为 0.002%，
**证明那 1.978% 是窗口重绘/动画造成的假阳性**，不是真实平移。

按项目要求「不得虚报测试通过」，特此更正。

## 根本原因（最终确认）

FCP 对**所有合成输入事件**（键盘、滚轮、Shift+滚轮）一律忽略。
唯一能被 FCP 接受的程序化控制方式只有 **AX 菜单点击**（用于缩放）。

这解释了为什么：
- ✅ 缩放可行 —— 有 `显示 > 放大/缩小` 菜单项可点
- ❌ 平移不可行 —— 没有任何平移菜单项，而事件注入被完全忽略
