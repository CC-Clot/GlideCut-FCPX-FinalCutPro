# 权限「明明授权了却仍提示不完整」—— 根因与解决

> 2026-11-23 00:47

## 问题现象

用户在系统设置里授权了 GlideCut，但应用设置窗口仍提示「权限不完整」。

## 根因（已确诊）

### 核心原因：adhoc 签名导致 TCC 身份不稳定

排查过程：
1. 本机 `security find-identity -v -p codesigning` → **0 valid identities**（无开发者证书）
2. 因此 Xcode 只能使用 **adhoc 签名**（`CODE_SIGN_IDENTITY = "-"`）
3. 实测验证 adhoc 签名的身份不稳定：
   ```
   重签前 CDHash: 0b1cd3e036a8df1e...
   重签后 CDHash: e85ee487b66ae63d...   ← 完全变了
   ```
4. **TCC 依据 CDHash + 路径识别应用**，每次重新构建/重签都会产生新的 CDHash
5. 结果：用户授权的是「旧身份」，应用运行的是「新身份」，TCC 认为是两个不同应用 → 授权失效

### 次要原因：两个权限是不同的 TCC 服务
- `CGPreflightListenEventAccess()` → **输入监控**（Input Monitoring）
- `AXIsProcessTrusted()` → **辅助功能**（Accessibility）
- 两者需**分别授权**，只授权一个仍会报"不完整"

## 解决方案（已实施）

### 创建固定的自签名证书

```bash
# 1. 生成自签名证书（含 codeSigning 用途）
openssl req -x509 -newkey rsa:2048 -keyout glidecut.key -out glidecut.crt \
  -days 3650 -nodes -subj "/CN=GlideCut Local Signing" \
  -addext "keyUsage=critical,digitalSignature" \
  -addext "extendedKeyUsage=critical,codeSigning"

# 2. 打包 p12
openssl pkcs12 -export -inkey glidecut.key -in glidecut.crt \
  -out glidecut.p12 -passout pass:glidecut -name "GlideCut Local Signing"

# 3. 导入钥匙串并信任
security import glidecut.p12 -k ~/Library/Keychains/login.keychain-db -P glidecut -T /usr/bin/codesign
security add-trusted-cert -d -r trustRoot -k ~/Library/Keychains/login.keychain-db glidecut.crt
```

结果：
```
security find-identity -v -p codesigning
  → 1) 15E3A853... "GlideCut Local Signing"   ✅
```

### 工程配置改为固定证书

`project.pbxproj`：
```
CODE_SIGN_IDENTITY = "GlideCut Local Signing";
CODE_SIGN_STYLE = Manual;
```

### 验证签名生效

```
codesign -dvvv /Applications/GlideCut.app
  Identifier=com.ccmac.GlideCut
  Authority=GlideCut Local Signing   ← 固定身份
  Signature     ← 不再是 adhoc
```

## 现在需要你做的

1. 在已打开的「输入监控」面板中，为 **GlideCut** 打开开关
2. 再打开「辅助功能」面板，同样为 GlideCut 打开开关
3. **退出并重启 GlideCut**（TCC 需要重启进程才生效）
4. 重新打开设置窗口，应显示「权限已就绪」

## 关键提醒

**这次授权后，只要不重新构建替换 `/Applications/GlideCut.app`，授权会长期有效。**

之前反复失效是因为我在不断重新构建（每构建一次 CDHash 就变一次）。
现在用固定证书后，同一份签名可长期使用。

如果以后我修改代码需要重新构建，授权可能需要重新给一次——
这是 macOS 对未公证应用的安全限制，无法绕过（也不应绕过）。
