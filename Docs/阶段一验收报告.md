## 三、滚轮事件监听技术验证报告

### 3.1 已验证：API 可用性与事件模型 ✅

在 MacOSX27.2 SDK 下用 `swiftc -typecheck` 逐个实测编译通过，确认以下 API 签名与枚举名（**均为实测，非猜测**）：

- 创建 Tap：`CGEvent.tapCreate(tap:place:options:eventsOfInterest:callback:userInfo:)` → `CFMachPort?`
- 事件类型：`.scrollWheel`、`.null`、`.tapDisabledByTimeout`、`.tapDisabledByUserInput`
- 事件字段：`.scrollWheelEventDeltaAxis1`、`.scrollWheelEventDeltaAxis2`、`.scrollWheelEventMomentumPhase`、`.scrollWheelEventScrollPhase`
- 读取增量：`event.getDoubleValueField(.scrollWheelEventDeltaAxis1/2)`
- 回调类型：`CGEventTapCallBack = (CGEventTapProxy, CGEventType, CGEvent, UnsafeMutableRawPointer?) -> Unmanaged<CGEvent>?`
- listen-only 模式下回调返回 `Unmanaged.passUnretained(event)` 即可，不拦截事件。

**结论**：监听物理鼠标滚轮、区分垂直/水平轴（axis1/axis2）、读取增量值的**代码路径已打通并编译通过**。

### 3.2 已验证：事件循环生命周期 ✅（代码层面）

- 事件投递通过 `CFMachPortCreateRunLoopSource` + `CFRunLoopAddSource` + `CFRunLoopRun` 建立。
- 停止流程：`CFRunLoopStop` → `CFMachPortInvalidate` → `CFRunLoopRemoveSource`，并用 `DispatchSemaphore` 等待后台线程结束（超时 3 秒）。
- 相关符号（`CFMachPortInvalidate`、`CFMachPortIsValid`、`CFMachPortGetPort`、`CFRunLoopRemoveSource`、`CFRunLoopStop`）均已实测可编译。

### 3.3 关键发现：`CFMachPortStart` / `CFMachPortStop` 在本 SDK 中不存在 ✅

三处独立验证均确认该符号不存在：

1. SDK 头文件 `.../CoreFoundation.framework/Headers/CFMachPort.h` 只声明 `Create / CreateWithPort / GetPort / GetContext / Invalidate / IsValid / Get / SetInvalidationCallBack / CreateRunLoopSource`；
2. SDK 的 `.tbd` 接口文件中无此符号；
3. 运行时 `nm -D /System/Library/Frameworks/CoreFoundation.framework/CoreFoundation` 无此符号。

社区 Swift 的 CGEventTap 实现（TripleTapMiddleClick、OpenWhispr 等）也均不调用这两个函数。**因此代码中不使用它们，改用 `CFMachPortInvalidate` 完成注销。**

### 3.4 未实测：真实事件监听 🟡

- **监听本身未做真实运行验证。** 原因是：调用 `CGEventTapCreate` 需要「输入监控」TCC 授权，而本阶段约束明确「不擅自申请辅助功能、输入监控权限」，因此**未申请、未实测**。
- 监听代码（`EventTapController` + `WheelTapProbe`）已就绪且编译通过，具备在用户授权后立即实测的条件。

### 3.5 未实测：监听期间对系统滚动的影响、退出后彻底停止 🟡

- 「监听时不明显影响系统正常滚动」「退出后彻底停止并恢复正常」两点，代码上以 **listen-only 模式**（不拦截、不修改事件）作为设计保障，但**未做真实运行验证**，需在授权后实测确认。

## 五、FCP 时间线缩放与平移技术可行性报告

### 5.1 结论：**用户给定的映射方案尚未确定，且与公开资料存在冲突 ❓**

本阶段对 FCP 的滚轮/缩放行为做了资料调研，**未对 FCP 时间线做任何实际操作**（遵守「未经同意不得造成时间线实际编辑或素材变化」的约束）。调研发现用户给定的映射与公开资料**不一致**，必须实测确认，**不能据此宣称功能可行或已实现**。

**用户给定的映射：**

| 操作 | 期望效果 |
|---|---|
| Command + 滚轮向上 | 时间线放大 |
| Command + 滚轮向下 | 时间线缩小 |
| Option + 滚轮 | 时间线水平平移 |
| Shift + 滚轮 | 保留 FCP 原生行为 |
| 普通滚轮 | 保留 FCP 原生行为 |

**公开资料证据：**

1. **Apple 官方文档**（[Final Cut Pro 时间线缩放与滚动](https://support.apple.com/en-cn/guide/final-cut-pro/ver4e2edcc/10.6.6/mac/12.6)）：
   - 放大时间线：`显示 > 放大` 或 **Command + 加号 (+)**
   - 缩小时间线：`显示 > 缩小` 或 **Command + 减号 (–)**
   - 缩放工具：**Z 键**；手型平移工具：**H 键**；或拖动滚动条。
   - **官方文档未提及用鼠标滚轮直接缩放或平移时间线。**

2. **CommandPost 开发者指南**（[plugins.finalcutpro.timeline.mousezoom](https://github.com/CommandPost/CommandPost-DeveloperGuide/blob/master/api/plugins/plugins.finalcutpro.timeline.mousezoom.md)）：
   - 明确说明：**按住 Option 键 + 机械滚轮 / Magic Mouse 触摸板，可对 FCP 时间线进行缩放**。
   - 这与用户给定的「Option + 滚轮 = 水平平移」**直接冲突**。

3. **社区资料**（[creativecow 论坛](https://creativecow.net/forums/thread/fastest-way-of-navigating-fcp-timeline/page/2)）：
   - 「Shift + 滚轮水平滚动」被描述为**系统级快捷键**（来自 macOS 系统设置中的鼠标滚动方向设置），**并非 FCP 特有行为**。

**冲突小结：**

- 「Command + 滚轮 = 缩放」—— 与 CommandPost 的「Option + 滚轮 = 缩放」冲突，且 Apple 官方未文档化滚轮缩放。
- 「Option + 滚轮 = 水平平移」—— 与 CommandPost 直接冲突。
- 「Shift + 滚轮」—— 公开资料认为是 macOS 系统级行为，而非 FCP 原生行为。

**因此，用户给定的映射方案属于 ❓ 尚未确定的技术方案，必须通过真实、安全的实测来确认，不得假设。**

### 5.2 技术路径分析 ❓

若要实现「滚轮控制 FCP 时间线」，技术上有两种路径，均**未经验证**：

1. **事件拦截 + 重新注入**：拦截滚轮事件，按映射合成新事件注入。
   - 需要验证：事件循环时序、重复触发、事件丢失、以及注入事件能否被 FCP 正确接收。
   - 注入事件通常还需要**辅助功能（Accessibility）**权限，权限链路比纯监听更重。
2. **合成键盘事件**：检测到「Command + 滚轮」后，合成 `Command + Plus/Minus` 键事件。
   - 这正是用户明确警示的「**不能简单地把普通滚轮事件转换成 Command + 或 Command - 就认定完成**」的做法——键事件可能作用于查看器或其他面板，而非时间线本身，存在误操作风险。

**关键风险**：无论哪种路径，都必须验证操作**确实作用于 FCP 时间线**，而不是浏览器式缩放、其他面板或界面。此点目前**完全未验证**。

## 六、macOS 权限需求与授权步骤

### 6.1 权限需求

| 权限 | TCC 服务 | 用途 | 是否必需 |
|---|---|---|---|
| **输入监控** | `kTCCServiceInputMonitoring` | 监听全局鼠标滚轮事件（CGEventTap） | **必需**（监听） |
| **辅助功能** | `kTCCServiceAccessibility` | 跨应用注入/操控事件 | 若需事件注入则必需；纯监听不需要 |

### 6.2 授权步骤（需用户手动操作）

1. 打开 **系统设置**。
2. 进入 **隐私与安全性** → **输入监控**。
3. 在列表中找到 **GlideCut**，打开开关，按提示确认。
4. （若后续需要事件注入）另在 **隐私与安全性 → 辅助功能** 中为 GlideCut 授权。
5. 授权后重启 GlideCut，再在菜单栏或设置窗口中打开监听开关。

### 6.3 说明

- TCC 数据库受 SIP 保护，普通用户**无法预读**授权状态，只能在应用运行时由用户在系统设置中手动授权。
- **本阶段未申请、未操作任何系统权限**，也未修改任何系统配置。
