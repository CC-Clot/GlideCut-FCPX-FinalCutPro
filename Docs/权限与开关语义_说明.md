# 权限与开关语义说明

## 一、你问的两个问题的答案

### Q1：「启用滚轮事件监听才能用对吧？」
**是的。** 它控制 CGEventTap 是否启动——这是所有功能的技术前提。

### Q2：「窗口中的启动滚轮增强又是什么意思？」
**这是我实现上的冗余设计，已修复。**

原来有两个开关：
| 位置 | 名称 | 内部字段 | 作用 |
|---|---|---|---|
| 菜单栏 | 启用滚轮事件监听 | `isListening` | 启动/停止 CGEventTap |
| 设置窗口 | 启用滚轮增强 | `featureEnabled` | 决定是否执行转换 |

**两者都必须开启才能工作**——这给用户造成理解负担，是我的设计失误。

### 修复
- 移除了 `featureEnabled` 的二次判断
- 设置窗口的开关改为直接绑定 `isListening`（与菜单栏同一个）
- 现在只有**一个概念**：开 / 关

## 二、权限的真相（你之前一直提示不完整的原因）

### 两个独立权限，都必须授权

| 权限 | 检测 API | 用途 |
|---|---|---|
| **输入监控** | `CGPreflightListenEventAccess()` | 监听滚轮事件 |
| **辅助功能** | `AXIsProcessTrusted()` | 驱动 FCP 菜单（缩放） |

**关键**：这是两个不同的 TCC 服务，必须在系统设置里**分别**授权。
只授权「输入监控」时，日志会显示：
```
权限状态：输入监控=已授权，辅助功能=未授权   ← 就是这个
```

### 另一个坑：同时运行两个实例
排查中发现：
```
/Applications/GlideCut.app       CDHash=8915f83e...  签名=GlideCut Local Signing
DerivedData/.../GlideCut.app     CDHash=0b1cd3e0...  签名=adhoc
```
两个签名不同的实例同时运行，会导致 TCC 授权混乱。
**解决**：只运行 `/Applications` 版，并用 `tccutil reset` 清空旧记录后重新授权。

## 四、当前使用方式（简化后）

1. 启动 GlideCut（菜单栏出现图标）
2. 权限就绪时**自动开启**，无需手动点开关
3. 在 FCP 里：**Command + 滚轮** → 时间线缩放
4. 普通滚轮 / Shift+滚轮 → 保持 FCP 原生行为
5. 需要暂停：菜单栏图标 → 关闭「启用滚轮事件监听」

## 五、重要提醒

**不要运行 DerivedData 里的版本**（adhoc 签名），只运行 `/Applications/GlideCut.app`（固定签名）。
否则 TCC 授权会再次混乱。

**每次我重新构建并替换 /Applications 里的 app，可能需要你重新授权一次**——
这是 macOS 对未公证应用的安全限制。已用固定证书最大程度缓解。
